Overview
What I built

Construction EHS (Environmental Health & Safety) teams typically pull OSHA enforcement data by hand and rebuild a compliance summary in Excel every reporting period — slow, repetitive, and error-prone. This project automates that entire workflow end to end: sourcing real government safety data, cleaning and modeling it, loading it into a relational database, and auto-generating a formatted compliance report with a single script run.

This is the third project in a three-part Data & Systems Analyst portfolio, and it's deliberately built with a distinct tool stack from the other two — plain Python and SQL, no BI GUI tool — to demonstrate automation engineering rather than dashboard visualization.

Data
Sourcing & validation

Sourced real, verified-live data from the U.S. Department of Labor's OSHA Enforcement Data via the DOL Open Data Portal — filtered to the Construction sector (NAICS prefix 23) and the last 5 years of inspections. Two joined tables: inspection-level case detail and citation-level violation detail.

Before writing any transform logic, I documented the grain, nullability, and meaning of every field in a data dictionary — a lesson learned the hard way on a prior BI project where undocumented field grain caused downstream modeling errors.

Pipeline
Clean, model, automate

Cleaned and transformed the raw data with pandas — fixing dtypes, dropping columns confirmed 100% null via EDA, decoding coded fields into readable labels, and deriving fields like violation severity rank. Every stage is quality-checked: pre-transform null/duplicate profiling, and post-transform validation of referential integrity, label coverage, and value sanity.

The cleaned data loads into a normalized SQLite database — two tables (inspections, violations) with proper primary/foreign keys and indexes, not a flat DataFrame dump. A Python script then queries that database and builds a multi-sheet, formatted Excel report using live formulas (COUNTIF/SUMIF against backing data sheets), so the report recalculates automatically if the underlying data changes — the actual automation deliverable that replaces the manual EHS reporting process.

Logging and error handling run throughout every stage of the pipeline for production-adjacent reliability. A bonus Streamlit dashboard sits on top of the same database for interactive exploration.

Deliverable
The report

The primary output: an 8-sheet Excel workbook — Executive Summary, breakdowns by violation severity, NAICS sub-sector, and state, a ranked list of the most frequently cited OSHA standards, and an open-cases tracker for follow-up.

Outcome
Results & learnings

Automated what would otherwise be a manual, repeated data-pull-and-report process into a single-command pipeline covering 400K+ real records, with zero duplicate/orphaned keys and under 3.2% "unknown" rate across every decoded field — validated at two separate quality-check stages.

The biggest lesson carried over from a prior project: document field grain before modeling, not after. Doing that upfront here made the cleaning and schema design far faster and caught several near-100%-null columns before they became dead weight in the database.
