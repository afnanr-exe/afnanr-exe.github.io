01: Objective
Why this project exists

This was the culminating project for the course: apply everything learned across the semester's labs to program a real robot, the eebot mobile platform, in assembly language using the CodeWarrior IDE. The goal was to make the robot navigate a maze by moving forward as far as possible, adjusting direction with two onboard sensors, reversing 180° when its bumper was triggered, and taking a secondary path when needed until it reached the exit.

02: Theory
A robot as a finite state machine

The guidance logic is structured as a Finite State Machine (FSM) implemented directly in 68HC11-family assembly. Sensor readings from two front sensors (referred to in code as E and F) continuously feed into the state logic, which decides whether the robot should keep going straight, correct its heading, treat a sensor trigger as a junction, or treat a bumper hit as a dead end requiring a 180° turn.

Key guidance parameters, including the distance required before reaching a junction, the turning distance, the current state, and threshold values, were all tuned specifically for the eebot's sensor characteristics and motor response, since these thresholds directly determine how reliably the FSM distinguishes "still on the path" from "at a junction."

03: Implementation
Startup, dispatch, and guidance

The assembly program is organized into three functional blocks:

  1. Guidance parameters: constants and thresholds controlling how sensitive the robot is to sensor triggers, junction distances, and turning behaviour.
  2. Startup & main routine: initializes port references, memory addresses, and accumulators, then invokes the display, state-detection, and dispatcher routines in sequence.
  3. Dispatcher (FSM core): uses JSR (jump-to-subroutine) calls and conditional logic to keep the robot in a forward-driving state by default, adjusting heading along the way, triggering a turn when sensor E or F crosses its threshold, executing a 180° turn at a dead end, and switching to a secondary path in the conjugate direction when required.
Reused foundations

Several code sections were directly repurposed or adapted from earlier labs in the course, including battery-voltage display routines and forward/backward state-table movement, underscoring how the semester's incremental labs built toward this final integration project.

04: Conclusion
What the project proved

The robot successfully completed the maze, validating both the FSM design and the sensor threshold tuning. More broadly, the project deepened the team's understanding of assembly language as a real tool for controlling physical hardware rather than just an academic exercise, and reinforced how much of embedded systems work is building on prior, simpler building blocks rather than starting from scratch each time.

The project's success affirmed the value of the course's earlier labs: fundamentals like reading a state table or displaying a sensor value on a battery-voltage readout turned out to be direct prerequisites for a working autonomous-navigation system.
